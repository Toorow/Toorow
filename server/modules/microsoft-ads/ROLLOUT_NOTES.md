# microsoft-ads — rollout notes

## Story 26.4 — new module (Bing Ads Reporting v13 REST, async)

First consumer of the 26.1 async socle in production shape:
`core.async_reports.run_async_report` drives every pull (Submit -> Poll ->
download ZIP CSV), `core.field_compat.enforce_selection` refuses Column
Restrictions pre-call, `core.refetch` ladder is 3/30/90.

### What landed

- Catalog COMPLETE AT EXECUTION (Jean's hard rule): 232 fields = 192 distinct
  columns integrally covering the 8 primary report types (Campaign 132,
  Account 111, AdGroup 104, Ad 92, Keyword 80, Geographic 80, SearchQuery 61,
  AgeGenderAudience 38 — live XSD enums, dossier 2026-07-21) + 40 excluded
  report-surface fields (`report-type-next-tier` reasons, one per remaining
  v13 ReportRequest type). ZERO `planned`.
- 6 profiles (AI-58): `campaign_daily`, `ad_group_daily`, `ad_daily`,
  `keyword_daily`, `search_query_daily` (exact_bundle) + `catalog_daily`
  (catalog_driven over the 8 whitelisted report types; the selection chooses
  the report type when not explicit).
- `field_compatibility` (core 26.1 contract, generated by
  `catalog_sources/build_official_fields.py`): 2 mutually_exclusive rules
  (impression-share vs restricted attributes; audience-share vs customer
  attributes) + 8 selectable_set rules (scope `{"report_type": ...}`, integral
  enums). The >=1 attribute + >=1 non-impression-share statistic invariant is
  module-enforced pre-call (rule id `request-invariants-min-attr-min-stat`).
- error_map keyed on the numeric BODY code (`<http_status>:<Code>`), body-first
  classification; `rate_limit_codes` 117/207/4204 -> `RateLimitError`
  (breaker re-queue) whatever the HTTP status; poll codes 2100/2101 on a known
  reference -> canonical async `expired` (26.1 F-3).
- Deferred outcome (CROSS-REVIEW FIX, orchestrator-imposed): a run that
  exhausts its polling budget raises a RETRYABLE `ProviderTransientError`
  carrying the `report_ref` + `request_hash` (amazon-ads pattern) — NEVER a
  `{"status": "deferred", "row_count": 0}` return, because `core/queue.py`
  does not read `result["status"]` and would mark the job done at 0 rows
  (an off-ladder backfill window would then never be re-pulled). The
  ReportRequestId stays persisted in flight and the queue's standard retry
  resumes by re-poll, never resubmits.
- Report-type inference guard (F-2): a catalog selection covered by SEVERAL
  report types of different grains that carries a NON-ADDITIVE statistic
  (impression share, ratios — generated `_non_additive_statistics` marker in
  the compat block) is refused with the candidate list; an explicit
  `report_type` disambiguates. Mono-candidate or purely additive selections
  keep the deterministic inference (inferred type + discarded candidates
  logged).
- Non-numeric statistic values (F-3): never dropped — reinjected into
  `segments_json` keyed by the catalog field_id, warning logged, and the
  pull result carries a `non_numeric_landed` counter.
- Request hash (F-4) is column-ORDER-insensitive (sorted before hashing);
  the Submit body keeps the caller's order.

### Verifications PROBE-ONLY (live pass required — AI-13 / 25.6, blocked)

These CANNOT be proven mocked; the 25.6 probe agent must ratify them live:

1. **Concurrent-report cap (code 207)** — the limit is "internal and subject
   to change" (undocumented). Measure how many simultaneous Submits a single
   customer tolerates; calibrate the manifest `quota` block (currently a
   conservative 30 points / 60 s) and confirm submits-serialized is enough.
2. **Real generation latencies** — official guidance polls every 2–15 min and
   generations can exceed 60 min. Validate the socle poll ladder
   (15 s -> 2 min) and the default `ASYNC_REPORT_DEADLINE_SECONDS=1500`
   against real accounts (small vs large); tune env if pulls defer too often.
3. **Download URL 5-minute expiry** — confirm the dead-URL status codes
   (403/404/410 assumed) and that re-poll issues a fresh URL.
4. **GoalsAndFunnels + Column Restrictions in real conditions** —
   GoalsAndFunnelsReportRequest is excluded (`report-type-next-tier`); confirm
   Goal/GoalType columns behave as restricted attributes on the covered
   reports, and probe the exact provider error (code) when an impression-share
   plus restricted-attribute combination slips through, to keep our pre-call
   rules byte-aligned with the live service.
5. **Attribute vs statistic classification** — QualityScore/ExpectedCtr/
   AdRelevance/LandingPageExperience/QualityImpact and bid columns are
   classified ATTRIBUTES, Historical* as statistics (dossier reading of
   "Columns that group the data"). A live 2015 RequiredColumnsNotSelected on a
   [TimePeriod + QualityScore + Impressions] probe would falsify it.
6. **CSV header names == enum names** and percent formatting — the parser maps
   headers via catalog `source_field` and strips a trailing `%` before decimal
   coercion (physical_type-driven); verify on real downloads (utf-8-sig,
   ""/"--" nulls, FormatVersion 2.0).
7. **Customer Management discovery headers** — `User/Query` + `Accounts/Search`
   are called with bearer + DeveloperToken only (CustomerId/CustomerAccountId
   unknown pre-selection). Confirm live that discovery succeeds without them.
8. **Nango provider key** — confirm the Nango integration id used for
   `get_fresh_token(connection_id, provider="microsoft-ads")` matches the
   configured Microsoft Identity integration (scopes
   `https://ads.microsoft.com/msads.manage offline_access`, tenant `common`),
   and that refresh-token rotation is persisted by Nango.
9. **Error body envelope** — the recursive `Errors[].Code` extractor assumes
   ApiFaultDetail/AdApiFaultDetail JSON shapes; capture one real 401/400 body
   per service as evidence.
10. **Sandbox first** — the universal sandbox developer token (`BBD37VB98`)
    can de-risk 1–9 before the production token approval lands.
11. **Poll Success of a genuinely EMPTY report (review F-6)** — the module
    treats `Status=Success` WITHOUT a `ReportDownloadUrl` as "report
    generated with zero data rows" (honest zero-row completion). Confirm on
    a real empty window that the provider actually omits the URL (vs. a URL
    to a headers-only CSV) so an omitted URL can never mask a real report.
12. **Snapshot vs status history (linked to transverse F-1 — story 26.6)** —
    mutable attributes (CampaignStatus, AccountStatus, names ...) land as
    snapshot values inside the supersede grain. The cross-module fix for
    mutable attributes in the supersede grain is story 26.6 (all 4 modules
    at once); probe what a re-pull of an old window does to rows whose
    status changed in between, as live evidence for 26.6.
13. **Draft accounts at Submit** — discovery keeps `Active` AND `Draft`
    accounts (Draft is selectable). Confirm live that SubmitGenerateReport
    on a Draft account succeeds (or capture the exact error code) so the
    topology filter and the error map stay truthful.
14. **2100/2101 inside an HTTP 200 envelope** — the purged-reference
    mapping (poll codes 2100/2101 -> canonical `expired`) currently only
    triggers on non-200 responses. Verify the live service never ships
    these codes in a 200 body (a 200-wrapped fault would today surface as
    "unknown status" -- loud, but not `expired`).
15. **Real pagination beyond 1000 accounts** — `Accounts/Search` paging
    (PageInfo Index/Size 1000, cap `_MAX_ACCOUNT_PAGES=20` with an explicit
    truncation warning when the cap is hit on a full page) is mock-proven
    only; validate index semantics on a customer with >1000 accounts.

### Regeneration

```bash
uv run python server/modules/microsoft-ads/catalog_sources/build_official_fields.py
uv run python scripts/build_api_catalog.py --module microsoft-ads \
    --sources-dir server/modules/microsoft-ads/catalog_sources \
    --report server/modules/microsoft-ads/catalog_sources/fusion-report.json
```

The builder regenerates `official_fields.json` AND the derived blocks inside
`catalog_sources.json` (`field_compatibility`, `excluded_fields`) from one
source (its column tuples) — zero drift possible. The Supermetrics snapshot is
optional enrichment (labels only): fetch it locally and add
`"file": "supermetrics.md"` to its source entry before regenerating if you
want the fusion `matched` counts refreshed; never commit the snapshot.
